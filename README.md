# Установка на Keenetic
1) Заходим в консоль Entware c логином и паролем admin-a роутера:
```sh
telnet 192.168.1.1
exec sh
```

2) Скачиваем и устанавливаем сервис:
```sh
opkg update
opkg install wget-ssl ca-bundle

cd /tmp
wget https://github.com/dimkinthepro/keenetik_adblock_dns/releases/download/0.1.0/adblock-dns_0.1.0_all.ipk

opkg install ./adblock-dns_0.1.0_all.ipk
/opt/etc/init.d/S56adblock-dns start

# Проверка статуса
/opt/etc/init.d/S56adblock-dns status

# Перезагрузка
/opt/etc/init.d/S56adblock-dns restart

# Остановка
/opt/etc/init.d/S56adblock-dns stop

# Просмотр логов
tail -f /opt/var/log/adblock-dns.log
```

# Настройка DNS на роутере
После этого в качестве DNS сервера указываем 192.168.2.1:553

# Описание adblock-dns

Пакет opkg (Entware) для роутеров Zyxel Keenetic, в том числе Viva. Поднимает
на роутере локальный DNS-сервер, который блокирует рекламные и трекерные
домены, а все остальные запросы пересылает вышестоящему DNS — по умолчанию
Google DNS (`8.8.8.8`, `8.8.4.4`). Всё поведение задаётся текстовыми конфигами.

В комплекте идёт готовый чёрный список на 911 доменов, собранный из
[v2fly/domain-list-community](https://github.com/v2fly/domain-list-community)
(категория `category-ads-all`).

---

## Как это устроено

Роль DNS-сервера играет **dnsmasq** — он не входит в пакет, а ставится
автоматически как зависимость (`dnsmasq-full`) из репозитория Entware.
Сам пакет состоит только из текстовых файлов: конфигов и двух shell-скриптов.

Цепочка запуска выглядит так:

1. При загрузке роутера Entware выполняет `/opt/etc/init.d/rc.unslung`,
   который по порядку запускает все скрипты вида `S*` из `/opt/etc/init.d/`.
2. Среди них — наш `S56adblock-dns`. Перед стартом сервиса он вызывает
   `/opt/bin/adblock-dns-update genconf`.
3. Скрипт `adblock-dns-update` читает `adblock-dns.conf`, берёт оттуда пути
   к чёрному и белому спискам, разбирает оба текстовых файла и генерирует
   в `/opt/var/adblock-dns/` два рабочих файла: `dnsmasq.conf` (порт,
   вышестоящие серверы, кэш) и `blacklist.conf` (правила блокировки).
4. Запускается `dnsmasq -C /opt/var/adblock-dns/dnsmasq.conf`.

Промежуточная генерация нужна потому, что dnsmasq не умеет читать список
голых доменов: он понимает либо hosts-формат (`0.0.0.0 домен`, но тогда не
блокируются поддомены), либо собственные директивы. Скрипт превращает каждую
строку чёрного списка в `address=/домен/0.0.0.0`, что блокирует домен вместе
со всеми поддоменами.

Домены из белого списка вычитаются из чёрного, а сверх того получают строку
`server=/домен/<вышестоящий DNS>`. В dnsmasq выигрывает наиболее конкретное
совпадение, поэтому белый список умеет «пробивать» блокировку внутри
заблокированной зоны: например, `126.com` остаётся заблокирован, а
`mail.126.com` резолвится нормально.

## Требования

- Keenetic с установленным Entware на USB-накопителе. Если Entware ещё нет,
  см. раздел ниже.
- Для варианта с нестандартным портом — прошивка 2.14 или новее.
- Накопитель должен оставаться в роутере: при его отсутствии сервис не
  стартует.

## Установка Entware на Keenetic

Шаги ниже сверены с официальной инструкцией Keenetic для Viva KN-1910
([support.keenetic.ru](https://support.keenetic.ru/viva/kn-1910/ru/20980.html)).

### 1. Компоненты прошивки

Управление → Общие настройки → Изменение набора компонентов. Нужны:

- **Поддержка открытых пакетов** (OPKG) — обязательный компонент;
- компонент поддержки файловой системы **EXT** — без него роутер не увидит
  ext4-раздел;
- **Сервер SSH** — если хотите заходить на роутер по SSH.

### 2. Подготовка накопителя

Отформатируйте USB-накопитель в **ext4** — это делается на самом роутере в
разделе управления USB-дисками. FAT32 не подойдёт: Entware нужны права
доступа и символьные ссылки, которых в FAT нет.

### 3. Установщик

В корне раздела создайте папку `install` и положите туда архив установщика
под архитектуру вашего роутера. Для **Viva** это mipsel:

```
https://bin.entware.net/mipselsf-k3.4/installer/mipsel-installer.tar.gz
```

Для моделей на ARM (Hopper, Titan, Ultra KN-1811) нужен
`aarch64-installer.tar.gz` из каталога `aarch64-k3.10/installer/`.

Выбирать архитектуру по выводу `show version` нельзя: Keenetic показывает
`arch: mips` в том числе для little-endian моделей вроде Viva, которым нужен
именно mipsel. Точное имя файла для конкретной модели указано в её
собственной версии официальной статьи — в адресе достаточно заменить
`viva/kn-1910` на свою модель.

### 4. Запуск установки

Вставьте накопитель в роутер, откройте Управление → Приложения → **Менеджер
пакетов OPKG**, выберите накопитель в поле «Накопитель» и сохраните. Роутер
сам распакует архив и развернёт Entware. Ход установки виден в системном
журнале на странице «Диагностика».

### 5. Доступ и проверка

Подключитесь по SSH на **порт 222**, логин `root`, пароль `keenetic` — это
шелл Entware, из которого дальше ставится наш пакет. Сразу смените пароль:

```sh
passwd
opkg update
```

Не путайте его с CLI самого роутера: команды вроде `ip name-server` и
`system configuration save` выполняются в интерфейсе Keenetic по SSH на
стандартном порту 22 под учётной записью администратора роутера.

## Сборка пакета

```sh
make            # собрать .ipk (только если файлы пакета менялись)
make rebuild    # пересобрать чёрный список из источников и затем .ipk
make clean      # удалить out/
make help       # список целей
```

`make` — обёртка над `build.sh`, который по-прежнему можно вызвать напрямую:

```sh
./build.sh
```

На выходе — `out/adblock-dns_1.1.1_all.ipk`. Пакет имеет архитектуру `all`,
потому что содержит только скрипты и конфиги, и подходит для любой модели
Keenetic независимо от процессора.

## Установка

Скопируйте `.ipk` на роутер и выполните в консоли Entware:

```sh
opkg install adblock-dns_1.1.1_all.ipk
/opt/etc/init.d/S56adblock-dns start
```

Проверьте, что сервер отвечает. Встроенный в busybox `nslookup` не умеет
указывать порт, поэтому нужен `dig`:

```sh
opkg install bind-dig
dig @127.0.0.1 -p 553 doubleclick.net +short   # ожидаем 0.0.0.0
dig @127.0.0.1 -p 553 ya.ru +short             # ожидаем реальный адрес
```

Автозапуск при загрузке роутера включается сам, отдельных действий не нужно.

### Подключение к роутеру (вариант по умолчанию, порт 553)

По умолчанию сервер слушает `127.0.0.1:553` и не занимает 53 порт — тот
остаётся за встроенным DNS-прокси Keenetic. Чтобы роутер начал обращаться к
нашему серверу, выполните в **CLI самого роутера** (это не SSH от Entware,
который висит на порту 222):

```
show ip name-server
no ip name-server
ip name-server 127.0.0.1:553
system configuration save
```

Порт указывается через `#`, а не через пробел.

Строка `no ip name-server` здесь важна: Keenetic опрашивает все прописанные
DNS-серверы параллельно и берёт первый пришедший ответ. Если в списке
останется любой публичный DNS, он отрезолвит ровно те домены, которые
блокирует наш сервер, и блокировка будет срабатывать через раз.

Плюс этой схемы в отказоустойчивости: если сервис не поднимется (например,
не смонтировалась флешка), роутер продолжит резолвить имена сам, просто без
блокировки рекламы.

### Альтернатива: занять 53 порт

Если хочется, чтобы клиенты обращались к серверу напрямую, поставьте
`LISTEN_PORT="53"` и `LISTEN_ADDR=""` (или LAN-адрес роутера) в конфиге, а
затем отключите встроенный прокси в CLI роутера:

```
opkg dns-override
system configuration save
```

и перезагрузите роутер.

Учтите риск: встроенный прокси при этом выключен, поэтому при любом сбое
сервиса или накопителя локальная сеть останется **вообще без DNS**, пока вы
не вернёте настройку вручную. Ещё нюанс — конфиг использует
`bind-interfaces`, поэтому интерфейс с указанным в `LISTEN_ADDR` адресом
должен существовать на момент старта службы.

## Конфигурация

Основной файл — `/opt/etc/adblock-dns/adblock-dns.conf`. После правки любого
из конфигов нужно перезапустить сервис:

```sh
/opt/etc/init.d/S56adblock-dns restart
```

| Параметр           | Назначение                                        | По умолчанию      |
|--------------------|---------------------------------------------------|-------------------|
| `UPSTREAM_DNS`     | Вышестоящие DNS, через пробел                     | `8.8.8.8 8.8.4.4` |
| `LISTEN_PORT`      | Порт прослушивания                                | `553`            |
| `LISTEN_ADDR`      | Адрес прослушивания, см. ниже                     | `127.0.0.1`       |
| `BLOCKING_ENABLED` | `no` — обычный форвардер без блокировки           | `yes`             |
| `BLOCKLIST_URLS`   | Ссылки на внешние списки для `adblock-dns-update` | StevenBlack hosts |
| `BLACKLIST_FILE`   | Путь к чёрному списку                             | см. ниже          |
| `WHITELIST_FILE`   | Путь к белому списку                              | см. ниже          |
| `CACHE_SIZE`       | Размер кэша dnsmasq в записях                     | `1500`            |
| `LOG_FILE`         | Файл лога, пусто — только syslog                  | пусто             |
| `LOG_QUERIES`      | `yes` логирует каждый запрос, для отладки         | `no`              |

`LISTEN_ADDR` управляет тем, кто может обращаться к серверу: `127.0.0.1` —
только сам роутер (рекомендуется вместе с портом 553), LAN-адрес роутера —
клиенты локальной сети напрямую, пустое значение — все интерфейсы.

### Чёрный и белый списки

Оба файла лежат рядом с основным конфигом, формат одинаковый: один домен в
строке, пустые строки и всё после `#` игнорируется, регистр не важен.

- `/opt/etc/adblock-dns/blacklist.txt` — блокируемые домены вместе с
  поддоменами. **Файл генерируется автоматически, править его не нужно** —
  свои домены добавляйте в `blacklist-source/manual.txt` (см. ниже).
- `/opt/etc/adblock-dns/whitelist.txt` — исключения. Действуют и на чёрный
  список, и на скачанные списки, и позволяют разблокировать поддомен внутри
  заблокированной зоны.

`whitelist.txt` и содержимое `blacklist-source/` помечены в пакете как
`conffiles`, поэтому ваши правки не будут затёрты при обновлении пакета.
`blacklist.txt` conffile'ом не является и при обновлении заменяется свежим.

Если что-то перестало работать, первым делом добавьте домен в белый список:
`category-ads-all` — список агрессивный, в него целиком входят, например,
`126.com` и `126.net` (NetEase).

### Внешние списки блокировки

Помимо встроенного чёрного списка можно подключить скачиваемые. Пропишите
ссылки в `BLOCKLIST_URLS` (понимается hosts-формат и простой список доменов)
и запустите:

```sh
adblock-dns-update
```

Команда перегенерирует конфиг, скачает списки, применит белый список и
перезапустит сервис. Если ни один список скачать не удалось, предыдущая
версия остаётся нетронутой.

Автоматическое обновление раз в сутки (нужен пакет `cron`):

```sh
echo "0 5 * * * root /opt/bin/adblock-dns-update" >> /opt/etc/crontab
```

### Источники чёрного списка и его пересборка

`blacklist.txt` собирается из каталога `/opt/etc/adblock-dns/blacklist-source/`:

- `manual.txt` — домены, которые вы добавляете руками. Они попадают в начало
  `blacklist.txt` и не дублируются в остальной части списка.
- `*.source` — описания внешних источников, по одному файлу на источник.
  В комплекте идёт `v2fly-ads.source` (v2fly/domain-list-community,
  `category-ads-all`); чтобы добавить свой, положите рядом ещё один файл.

Формат `*.source` — переменные shell:

```sh
TYPE="hosts"   # hosts - обычный hosts-файл или домен в строке;
               # v2fly - tar.gz репозитория v2fly с директивами include:
URL="https://example.com/list.txt"
LIST="category-ads-all"   # только для TYPE="v2fly": стартовый список в data/
```

Пересборка на роутере (скачивает источники заново, для v2fly это ~10 МБ):

```sh
adblock-dns-blacklist
/opt/etc/init.d/S56adblock-dns restart
```

Пересборка встроенного в пакет списка на рабочей машине:

```sh
./tools/update-blacklist.sh
./build.sh
```

Для v2fly скрипт рекурсивно разворачивает директивы `include:` и пропускает
записи `regexp:` и `keyword:` — их dnsmasq сопоставлять не умеет. Если ни один
источник скачать не удалось, прежний `blacklist.txt` остаётся нетронутым.

## Логи

По умолчанию dnsmasq пишет в `/opt/var/log/adblock-dns.log` и логирует каждый
запрос — так видно и то, что на сервис вообще что-то приходит, и то, как
отрабатывают списки.

```sh
tail -f /opt/var/log/adblock-dns.log
```

Строки читаются так:

```
query[A] doubleclick.net from 192.168.2.15     запрос пришёл от клиента
config doubleclick.net is 0.0.0.0              сработал чёрный список
forwarded ya.ru to 8.8.8.8                     ушёл вышестоящему DNS
reply ya.ru is 87.250.250.242                  ответ вернулся клиенту
cached ya.ru is 87.250.250.242                 отдано из кэша
```

Признак работающей блокировки — строка `config <домен> is 0.0.0.0`: она
означает, что ответ выдан из `blacklist.conf`, а не получен извне.

Сводку по кэшу (попадания, промахи, размер) можно получить в любой момент:

```sh
adblock-dns-update stats
tail -20 /opt/var/log/adblock-dns.log
```

### Ограничение размера

За размером следит сам пакет: при старте сервиса и при каждом запуске
`adblock-dns-update` файл проверяется и, если перерос `LOG_MAX_KB`,
переименовывается в `.log.1` (хранится `LOG_KEEP` копий). Потолок занимаемого
места — примерно `LOG_MAX_KB × (LOG_KEEP + 1)`.

```sh
LOG_FILE="/opt/var/log/adblock-dns.log"
LOG_QUERIES="yes"
LOG_MAX_KB="512"
LOG_KEEP="1"
```

Между этими проверками файл ничем не ограничен, поэтому при включённом
`LOG_QUERIES` стоит добавить в `/opt/etc/crontab` ежечасную проверку:

```
0 * * * * root /opt/bin/adblock-dns-update logrotate
```

Ротация не теряет строки: файл переименовывается, после чего dnsmasq получает
`SIGUSR2` и открывает путь заново.

Если логи не нужны совсем — `LOG_QUERIES="no"` (останутся только события
старта и ошибки) или `LOG_FILE=""` (всё уйдёт в системный журнал Keenetic).
Учтите, что `/opt` живёт на USB-накопителе: постоянная запись лога — это
износ флешки, так что на постоянку `LOG_QUERIES="yes"` лучше не оставлять.

## Удаление

```sh
opkg remove adblock-dns
```

Скрипт `postrm` вернёт на место штатный автозапуск dnsmasq и удалит рабочий
каталог `/opt/var/adblock-dns`. Если вы отключали встроенный DNS-прокси
роутера, не забудьте вернуть его в CLI Keenetic:

```
no opkg dns-override
system configuration save
```

## Структура

```
adblock-dns/
  CONTROL/
    control        метаданные и зависимости (dnsmasq-full, wget-ssl)
    conffiles      файлы, правки в которых сохраняются при обновлении
    postinst       постустановочные действия и инструкция
    prerm          остановка сервиса перед удалением
    postrm         откат изменений после удаления
  data/opt/
    bin/adblock-dns-update              генератор конфига и обновление списков
    bin/adblock-dns-blacklist           сборка blacklist.txt из blacklist-source/
    etc/init.d/S56adblock-dns           init-скрипт Entware (автозапуск)
    etc/adblock-dns/adblock-dns.conf    основной конфиг
    etc/adblock-dns/blacklist.txt       чёрный список (генерируется)
    etc/adblock-dns/whitelist.txt       белый список
    etc/adblock-dns/blacklist-source/manual.txt       свои домены
    etc/adblock-dns/blacklist-source/v2fly-ads.source источник v2fly
Makefile                                цели сборки (build/rebuild/clean)
build.sh                                сборка .ipk
tools/update-blacklist.sh               пересборка чёрного списка в репозитории
out/                                    готовый пакет
```

На роутере после установки появляются рабочие файлы в `/opt/var/adblock-dns/`
(`dnsmasq.conf`, `blacklist.conf`, `blocked.hosts`, `dnsmasq.pid`). Они
генерируются автоматически при каждом старте сервиса, править их не нужно.

## Замечания

**Конфликт со штатным автозапуском dnsmasq.** Пакет `dnsmasq-full` приносит
собственный init-скрипт `/opt/etc/init.d/S56dnsmasq` с `ENABLED=yes`. Без
вмешательства он поднимал бы второй экземпляр dnsmasq со своим конфигом.
Дополнительно `rc.func` в Entware ищет процессы через `pidof dnsmasq` и
завершает их через `killall dnsmasq`, поэтому два сервиса с одинаковым
именем процесса мешали бы друг другу. При установке `postinst` останавливает
штатный скрипт и переименовывает его в `.S56dnsmasq.disabled-by-adblock-dns`
(файлы не на заглавную `S` система автозапуска игнорирует), а `postrm`
возвращает обратно. Учтите, что обновление самого `dnsmasq-full` может снова
создать `S56dnsmasq` — тогда переустановите adblock-dns.

553 спроектирован так, чтобы отказ накопителя не оставил сеть без DNS.
